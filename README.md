# diehard-run-ekb-bot

Telegram-бот бегового чата Diehard в Екатеринбурге. Первая версия приветствует
пользователя после команды `/start`.

## Рабочее окружение и деплой

Бот размещён в отдельном каталоге
[`diehard-run-ekb-bot`](https://console.yandex.cloud/folders/b1g8lql532mgpncbv2q5/dashboard).
Идентификаторы ресурсов без секретов сохранены в `deploy/production.json`.
Функция, API Gateway, сервисный аккаунт, Lockbox и группа логов находятся в этом каталоге.
Функция приватная; шлюз вызывает её от сервисного аккаунта с правом только на эту функцию.
Токены берутся из Lockbox. Пользовательская VPC для этого окружения не используется.

Штатный деплой из корня проекта (Python 3.12, установлены `.[dev]`, настроен `yc`):

```bash
python -m scripts.deploy
```

Скрипт запускает Ruff и тесты, упаковывает только код/зависимости/ресурсы бота,
сохраняет текущие переменные и ссылки на версии секретов, создаёт кандидата,
проверяет ответы 401/200 и переключает тег `production`. Затем проверяет шлюз;
при ошибке проверки возвращает прежний тег. Проверки не отправляют сообщения людям.
Это проверка загрузки и авторизации, а не замена ручной проверки `/start` и вступления.
Параллельные деплои запускать нельзя. `$latest` не используется для рабочего трафика.

Для тега `production` включён `provisioned_instances_count=1` — минимальный
прогрев (суммарно по зонам согласно API; справка CLI неоднозначна). Простой подготовленных
экземпляров оплачивается отдельно. Политика привязана к тегу, а не к ID версии,
поэтому сохраняется при штатном деплое. После изменения настройки или версии
прогрев не мгновенный; при нагрузке сверх подготовленной ёмкости возможны
холодные старты дополнительных экземпляров.

Откат на версию из вывода предыдущего деплоя:

```bash
python -m scripts.deploy --rollback VERSION_ID
```

Нужны действующая авторизация `yc`, права создавать версии/менять тег функции,
использовать её сервисный аккаунт, читать настройки шлюза и payload секрета Lockbox
для проверок. Локальный `.env` скрипт не читает; секреты не пишет на диск и не выводит.
Глобальный каталог в настройках `yc` скрипт не меняет.

Для первоначального создания окружения есть отдельный скрипт
`python -m scripts.bootstrap_scope --cloud-id CLOUD_ID --source-function-id FUNCTION_ID`.
Он создаёт/находит именованные ресурсы и проверяет новый шлюз, но не переключает
Cloudflare. Повторные деплои выполняются только через `scripts.deploy`.

Прежние ресурсы в `default` сохранены как резерв для отката миграции.
Для возврата маршрута можно восстановить прежний `UPSTREAM_URL` в Cloudflare:
`https://d5dliqii8jqpnf7m7qkt.7qsg961h.apigw.yandexcloud.net/webhook`.
Telegram webhook при миграции не меняется, очередь не сбрасывается.

## Пятничное напоминание о регистрации

- `/start` в личном чате включает подписку и показывает уведомление об этом
  в подписи приветственного фото. `/subscribe` включает её без приветствия.
- `/unsubscribe` отключает напоминания. В групповых чатах подписка не создаётся.
- `/reminder_test` присылает пример только вызвавшему команду пользователю.
  Команда не запускает рассылку и не меняет подписку/отметку недельной доставки.
- Старым пользователям нужно один раз отправить `/start` или `/subscribe`:
  Telegram не предоставляет список исторических пользователей бота.
  Само вступление в группу не подписывает: доступ по заявке может быть временным.

Подписчики хранятся в отдельной serverless YDB внутри каталога бота.
Храним только ID чата, флаг подписки, время подписки и служебное состояние доставки;
имена, телефоны, сообщения не сохраняются. База ограничена 1 ГБ и 10 RU/s,
выделенная мощность отключена. Авторизация — через сервисный аккаунт функции.

Приватная функция `registration-reminders` запускается таймером
`friday-registration`. Начало отправки — **пятница 12:00 Europe/Moscow (09:00 UTC)**.
Cron `* 9 ? * FRI *` повторяет обработку каждую минуту в течение часа для очередных
пакетов и временных ошибок. Получатели выбираются из подписавшихся к 12:00.
Для каждого сохраняется дата пятницы; успешно отправленное сообщение не повторяется.
Транзакционная аренда на 120 секунд защищает от параллельной обработки.
Блокировка бота отключает подписку. Telegram 429 останавливает пакет;
сетевые ошибки откладываются, после 13:00 МСК рассылка не догоняется.
Если отправка прошла, а запись результата в базу оборвалась, возможен редкий дубль:
Telegram `sendMessage` не поддерживает идемпотентный ключ.

`scripts/setup_reminders.py` создаёт базу, схему, приватную функцию и ограниченные
права. Параметры из его вывода сохраняются в `deploy/production.json`.
Обычный `python -m scripts.deploy` теперь обновляет обе функции: сначала бота,
затем рассыльщик (после проверки доступа к таблице). При сбое второй стадии
бот остаётся на новой версии, рассыльщик — на предыдущей. Флаг `--rollback`
откатывает только webhook-функцию. Таймер сохраняется между деплоями.
После первого успешного деплоя `python -m scripts.setup_reminders --enable-timer`
включает расписание. Эта команда идемпотентна по имени и не меняет существующий таймер.
У рассыльщика нет платного прогрева. За YDB/вызовы/хранение логов действуют отдельные тарифы.

## Запуск через Cloudflare Relay и Yandex Cloud Functions

Ниже — справочная инструкция ручного развёртывания; рабочий деплой описан выше.

Из-за недоступности Telegram API из Yandex Cloud запросы идут через небольшой
Cloudflare Worker в обе стороны:

```text
Telegram -> Cloudflare Worker -> API Gateway -> Cloud Function
Cloud Function -> Cloudflare Worker -> Telegram Bot API
```

Worker не хранит сообщения. Он проверяет webhook-секрет, пересылает обновление
функции и разрешает Bot API-запросы только для токена этого бота.

### 1. Yandex Cloud Function

1. Создайте ZIP-архив для загрузки в Cloud Functions:

   ```bash
   zip -r function.zip index.py requirements.txt bot \
     -x '*__pycache__*' '*.pyc'
   ```

2. Создайте функцию с параметрами:

   - среда выполнения: Python 3.12;
   - точка входа: `index.handler`;
   - память: 512 МБ;
   - таймаут: 30 секунд;
   - публичная функция: включена;
   - подключение к пользовательской VPC: не требуется.

3. Добавьте переменные окружения функции:

   - `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather);
   - `WEBHOOK_SECRET` — случайная строка для проверки запросов Telegram;
   - `CHAT_INVITE_URL` — ссылка приглашения с одобрением заявок для кнопки
     «Присоединиться к чату» в `/start`. Если не задана, приветствие приходит без кнопки.
   - `WELCOME_PHOTO_URL` — публичный HTTPS-адрес приветственного фото (пример в
     `.env.example`). Telegram скачивает фото сам; функция не загружает файл через релей.
     Без переменной используется локальный файл. После успешной отправки `file_id`
     кешируется в памяти экземпляра функции. Ошибка или таймаут фото не блокируют текст
     приветствия и правила. Таймаут фото — 3 секунды, остальных API-запросов — 8 секунд,
     всей обработки — 25 секунд. При ошибке обработки возвращается 503 для повтора Telegram.

4. Создайте API Gateway с POST-маршрутом `/webhook`, интегрированным с функцией,
   и сохраните адрес вида `https://<gateway>.apigw.yandexcloud.net/webhook`.

### 2. Cloudflare Worker

Для деплоя нужен Node.js. Из корня репозитория выполните:

```bash
cd relay
npx wrangler login
npx wrangler secret put BOT_TOKEN
npx wrangler secret put WEBHOOK_SECRET
npx wrangler secret put UPSTREAM_URL
npx wrangler deploy
```

Wrangler запросит значения интерактивно:

- `BOT_TOKEN` — тот же токен BotFather, который задан в функции;
- `WEBHOOK_SECRET` — тот же секрет, который задан в функции;
- `UPSTREAM_URL` — полный адрес API Gateway с `/webhook`.

После деплоя сохраните адрес Worker вида
`https://diehard-run-ekb-bot-relay.<account>.workers.dev`.

### 3. Подключение функции к relay

Создайте новую версию функции на Python 3.12 и добавьте к существующим
переменным окружения:

```text
TELEGRAM_API_BASE_URL=https://diehard-run-ekb-bot-relay.<account>.workers.dev
```

Пересоберите ZIP перед загрузкой, чтобы в нём был обновлённый `index.py`:

```bash
zip -r function.zip index.py requirements.txt bot \
  -x '*__pycache__*' '*.pyc'
```

### 4. Регистрация webhook

В локальном `.env` укажите адрес Worker:

```text
WEBHOOK_URL=https://diehard-run-ekb-bot-relay.<account>.workers.dev/webhook
```

Затем зарегистрируйте webhook с компьютера, на котором доступен Telegram API:

```bash
set -a
source .env
set +a
python -m scripts.set_webhook
```

Откройте бота в Telegram и отправьте новый `/start` после регистрации webhook.

## Допуск в группу после принятия правил

Бот обрабатывает заявки на вступление (`chat_join_request`). До подтверждения
правил пользователь остаётся в списке заявок и не является участником группы.

Настройка тестовой группы:

1. Добавьте бота в группу как администратора.
2. Выдайте ему право приглашать пользователей — оно требуется для одобрения
   заявок.
3. Создайте ссылку-приглашение с включённой опцией запроса одобрения
   администратором.
4. Отзовите обычные ссылки-приглашения, позволяющие войти без заявки.
5. Если у группы есть публичный username, убедитесь, что через него нельзя
   вступить напрямую. Для строгого режима на время MVP сделайте группу частной.

После перехода по ссылке пользователь нажимает «Подать заявку». Telegram даёт
боту временную возможность написать заявителю в личный чат. Бот отправляет
правила и персональную кнопку подтверждения, затем предлагает простую
тематическую каптчу. Только после правильного ответа бот одобряет заявку.

Каптча и её кнопки подписаны webhook-секретом и привязаны к Telegram ID
заявителя и конкретной группе. Неверный ответ можно исправить повторным
нажатием; лимит попыток в этой базовой версии не используется.

После добавления этого сценария webhook нужно зарегистрировать повторно: список
`allowed_updates` должен включать `chat_join_request` и `callback_query`.

Файл `.env` исключён из Git и Docker-контекста. Не публикуйте токен бота,
webhook-секрет и содержимое `.env`.

## Локальный запуск через Docker

Этот режим использует long polling и нужен только для разработки в сети, где
доступен `api.telegram.org`.

1. Создайте и заполните `.env`:

   ```bash
   cp .env.example .env
   ```

2. Запустите бота:

   ```bash
   docker compose up --build -d
   ```

3. Откройте бота в Telegram и нажмите «Начать».

Посмотреть журнал работы:

```bash
docker compose logs -f bot
```

Остановить бота:

```bash
docker compose down
```

## Разработка без Docker

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
BOT_TOKEN=your-token python -m bot.main
```
